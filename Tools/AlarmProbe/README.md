# 独立提醒验证工具

这是给开发验证使用的独立程序，**不是0.1.3的提醒功能，也不是已经可靠的后台闹钟**。它不随正式应用打包、不连接正式数据库、不启动或退出正式软件、不改变进度。

已完成无声逻辑、程序编译及无许可时的拒绝路径检查；另经两次分别明确的授权，执行过2次清醒声音试验。**首次请求至播放接口成功约10.951秒耗时未定位，最终90秒外部超时；第二次约0.566秒至播放成功观察、正常退出，操作人事后已确认听到且一直重复直到手动停止，本次基础发声、手动停止与正常退出已有证据。准时性和完整提醒链路仍未验收，第一阶段仍未通过。** 第二次未重现长耗时不等于首次问题已修复。完整音频时序、稍后、锁屏、睡眠和主程序退出后的完整提醒链路尚未验收，请不要把它用于重要提醒。

## 为什么需要它

原有虚拟时间模拟不能证明 macOS 真能到点发声。此工具把以下证据分开：

1. 设定的到点时间。
2. 程序在何时检测到到点，以及回调偏差。
3. 音频播放接口何时返回成功；这还不证明扬声器有声音。
4. 人何时点击“已听到”和“确认停止”；点击含反应时间，不能当作第一声的精密测量。
5. 是否超出允许偏差、安全时限、发生时钟变化或记录失败。

工具不会自动给出“通过”。在到点检查中发现超出允许回调偏差或时钟异常时，会中止而不请求补响；这是**验证工具的安全规则，不是正式软件尚未确定的迟到提醒策略**。它不监测或阻止系统睡眠，不能保证识别每一次睡眠；音频准备是在这次检查之后同步执行的，准备变慢可能继续延迟播放，不能声称所有迟到都会被阻止。

## 使用的工具与文件

仅依赖本机已有 Swift 6、macOS SDK、Python 3，以及 Apple 的 Foundation、AppKit、AVFoundation。无需下载第三方库或铃声。

- `ProbeSession.swift`：输入时间、状态和允许偏差；输出“请求播放／停止／不处理”，没有音频或任务入口。
- `ProbeOptions.swift`：必须明确提供音频许可和四项参数；无参数默认拒绝。
- `ProbeTone.swift`：在内存生成660Hz、1.2秒循环周期的测试音；每周期约0.45秒发声、其余静音，首尾渐变。生成数据本身不打开音频设备。
- `ProbeLog.swift`：统一JSON编码，时间为保留小数的Unix秒；`ProbeTrace` 纯内存记录分段起止与返回／抛错，不打开音频或写文件。
- `ProbeMain.swift`：独立原生窗口、音频播放、手动观察、状态与退出处理。
- `../alarm_probe.py`：只有 `test`、`build`，没有自动响铃步骤。输出在仓库 `.build-local/alarm-probe/`。
- `../../Tests/AlarmProbeChecks.swift`：虚拟时间及参数、音频数据格式、记录精度与分段证据检查。
- `../../Tests/AlarmProbeSafetyChecks.py`：只跑帮助与无许可／无效参数拒绝路径。

## 安全的无声构建和检查

在仓库根目录执行：

```sh
python3 -B Tools/alarm_probe.py test
python3 -B Tools/alarm_probe.py build
python3 -B Tests/AlarmProbeSafetyChecks.py
.build-local/alarm-probe/alarm-probe --help
```

- `test` 不导入 AppKit／AVFoundation，不打开窗口或音频设备，只用虚构时间。
- `build` 只编译，不运行提醒窗口，不改 `dist/时间便签.app`。
- 安全启动检查不会传完整有效的音频许可组合；不会建立试验记录。
- 本工具不进入 `build.py app` 或 `build.py test`，不会因为正常构建／数据检查就启动声音。

## 真实发声之前必须确认

真实发声要单独确认，不能因为完成构建就自动开始。请先确定环境适合、工作已保存，不在会议或通话中，不戴耳机，并由操作人自行核对当前输出设备和合适的系统音量。程序**不读取或修改系统音量**；播放器0.15只是相对增益，不是15%的系统音量，更不保证固定响度。

实际运行须同时提供：

- `--approve-audio`：本次允许音频试验。
- `--delay`：从点击开始到提醒的秒数，5–300。
- `--tolerance`：本次允许的回调偏差，0–5秒。不是产品验收标准，尤其不等于测得第一声偏差。
- `--max-duration`：从点击开始计的安全时限；必须晚于到点并留出容差，最多900秒。
- `--volume`：播放器相对音量，大于0且不超过0.25。

这里不提供可以直接复制误启动的完整发声命令；应在具体试验申请中确定数值、操作时刻和时长。参数全部有效后也只打开准备窗口，**仍需点击“开始本次已批准试验”**才安排虚构提醒。

### 窗口操作

1. 核对显示的延迟、偏差、安全时限和播放器音量。
2. 点击开始；一次进程只做一轮，重新试验必须退出后重新发起。
3. 到点后若听到，点击“记录：我已听到声音”。不要因为界面写着播放就假定听到。
4. 点击“关闭本次提醒”；确认声音实际停止后，再点击对应记录按钮。
5. 如另行批准稍后试验，点击“稍后5分钟”，确认停止后等待300秒再听；安全时限不足时按钮禁用，不能把等待5秒假称通过5分钟。
6. 完成观察后退出。窗口关闭、Esc、⌘Q或“中止并退出”都会请求停止并退出本次程序。

### 异常中止

- 窗口卡住或声音未停：在启动该进程的终端按Ctrl-C结束**本次**程序；不要按模糊名称批量结束其他应用。
- 实际执行必须配合已批准的外部进程超时（例如由启动脚本使用 `subprocess.run(..., timeout=90)` 限定这一条子进程），以防窗口主线程阻塞时内部时限不能执行。外部超时要覆盖等待点击时间，并明确记录是中止，不是通过。
- 内部安全时限使用 `ContinuousClock`，不以人工调整系统时刻延长试验。安全时限触发只停止播放／计时，窗口保留结果等待退出；**不能宣称这是操作系统级硬保证**。到点日志写入、WAV生成、播放器初始化和播放调用都同步占用窗口的主执行路径；任一步卡住时，按钮和内部安全检查都可能不能及时处理。这是源码确认的风险，不是首次长耗时的已证实原因。
- Ctrl-C或外部超时不保证保存最后一条退出记录；缺失证据须报告，不能补造“正常退出”。
- 没有注册登录项、后台服务、通知、电源唤醒或阻止睡眠，因此无需撤销这些设置。仍应核对本次进程确已结束且声音停止，不能只看日志写了“停止”。

## 记录在哪里，包含什么

点击开始后，在可执行文件同目录建立唯一的 `trial-UUID/`，记录 `events.json`。通过本仓库的构建方式运行时，它位于 `.build-local/alarm-probe/`，不会进入Git。

记录只含随机试验编号、进程编号、系统版本、参数、状态事件、时刻及用户点击的观察。没有正式任务、数据库内容、录音、屏幕画面、凭据或联网请求。目录只允许当前用户访问；JSON采用原子替换，写入失败会中止并停止声音。

- `at`、`due`：带小数的Unix秒，起点为1970-01-01 UTC。
- `elapsed`：连续时钟相对秒数。
- `lateness`：检测到点的回调偏差，**不含之后写日志、准备音频及扬声器输出的延迟**。
- `soundRequested`：无声逻辑提出播放请求，不是声音已抵达扬声器的证明。
- `observations`：播放接口返回以及人工点击的时刻和说明。
- `verdict`：始终提示需要人工及场景证据，不自动变成“通过”。

### v2 分段证据：定位耗时，不伪造第一声

首次试验使用 `timenote-alarm-probe-v1`，原记录保持不动。后续诊断版报告格式为 **`timenote-alarm-probe-v2`**，新增 `timings`，每项包含：

- `step`：`persist`（编码及原子写入）、`waveData`（内存生成WAV）、`playerInit`（初始化播放器）、`playCall`（调用播放）、`stopCall`（调用停止）。
- `began` / `ended`：分别含 `at`（Unix小数秒）与 `elapsed`（连续时钟相对秒）；耗时用两次 `elapsed` 的差计算。
- `outcome`：`returned` 只表示调用返回，不等于业务成功或有声音；`threw` 表示抛错且原错误照常传播。未结束时 `ended`、`outcome` 不写出，读取方不能默认成功。

窗口收到关闭、稍后、退出请求，以及停止接口返回时，另记软件观察。终止回调记录不再声称进程已经退出，必须与启动器退出码／回收结果对照。

**记录自身的边界：** 这些时间先在内存收集，沿用原来写盘时机，不为每个时间点额外写文件。一次 `persist` 写入的快照不可能包含该次写入完成时间，因此最后一条 `persist` 没有结束字段是预期现象，不能据此认定卡死；结束时间只会进入下一次成功快照。强制终止可能丢失尚未保存的分段记录。`persist` 包含编码和写文件合计耗时，不再细分；播放器属性设置、释放和日志记录本身也有开销，不把所有未分配时间随意归到音频设备。

分段记录不改变发声时机、播放参数或容差，不提前初始化或预热音频。诊断版随后另获一次授权并执行清醒复测，取得真实分段与正常退出证据，结果见下文；**首次约11秒的根因仍未定位，也没有证明修复。**
